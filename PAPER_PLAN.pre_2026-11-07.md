# Paper Plan

**Title**: Execute the Program: Auditing Search and Tool Use in Mesh-to-CAD Reconstruction
**One-sentence contribution**: In an audited IoU-driven mesh-to-CAD optimizer (CADFit and our extensions), scoring the solid that the final program actually builds — rather than the mesh the search reports — changes which search improvements count, and giving open-weight LLM agents the optimizer's stages as tools lifts all six tested models by 0.26–0.47 executed-CAD IoU, although a scripted policy over the same tools is not shown to be worse than any agent.
**Venue**: ICLR (9 pages main body); honest fit: strong workshop / borderline main
**Type**: diagnostic (controlled audit) + one geometric intervention
**Date**: 2026-10-17
**Page budget**: 9 pages: front matter + intro + hero 2.0; related 0.5; setting & measurement 1.5; search 1.75; agents 2.25; discussion + conclusion 0.75; reserve 0.25
**Section count**: 7 + appendix

All numbers are generated from results/*.json (bench/paper_stats.py); intervals are paired percentile bootstrap over parts (10k, seed 0) and reflect part sampling only, not episode randomness. The manuscript must take numbers from those files (macros generated by a script), not from this plan.

## Structure

### §0 Abstract (~200 words)
Lead with the evaluation question (does reported mesh fidelity reflect the program?), then: fresh 60-part cohort; beam arm 0.880 mesh vs 0.799 executed (9/60 failed or invalid programs, nearly all of the gap from unbuilt programs); executed-CAD gains shrink vs mesh gains; whole-part section proposals give the largest executed-CAD increment (concentrated in one split). Then: six open-weight models, skills vs code, +0.26–0.47 IoU(CAD), Bonferroni-significant for all; best agent's mean 0.012 below the pipeline on the same parts; end with the open policy question (budget-matched script result, repeats). No "within ~0.05", no "D best" as the takeaway.

### §1 Introduction (≈1.25 pp + hero)
- Hook: the deliverable of mesh-to-CAD is a program; evaluation should run it.
- Gap (precise, no "nobody asks"): CADFit reports invalid ratio and executes candidates, but in the audited implementation with exact-union scoring the final composed program is never executed when scored; LLM CAD agents (CAD-Assistant, CADFather) use tools but leave open how much of the gain comes from the tools versus the model's selection policy (CADFather §4.6 says so explicitly).
- Three questions (Q1–Q3) organise the paper.
- Contributions: (1) execution-based audit protocol and its consequences on a never-inspected cohort; (2) whole-part section proposals as a geometric intervention that survives execution (with split caveat); (3) controlled tool-use study of six open-weight agents with code-only, skills, section-only ablation, repeats, and unrestricted + budget-matched scripted policies.
- Transition sentence before agents: "Having identified which geometric proposals survive execution, we test what agents gain from access to these operations."
- Hero Fig 1 (see figure plan).

### §2 Related Work (0.5 p)
Compact comparison paragraph + small table: method | input | geometric tools | final program executed in eval | policy control. Rows: CADFit, CAD-Recode, CAD-Assistant, CADFather, ours. Plus one paragraph on reconstruction datasets/metrics (ABC, DeepCAD, Fusion 360, CADBench; IoU/CD; GWN).

### §3 Setting and measurement (1.5 pp)
3.1 Task + CADFit recap (exact code revision and config audited). 3.2 Defects found (one-line each, table in appendix). 3.3 Protocol: judge (exact booleans else GWN MC), CAD replay in sandbox, validity convention + gated score, fresh cohort, stats (bootstrap over parts; Bonferroni over 6 models; intervals do not reflect episode randomness).

### §4 What survives execution: search arms on a fresh cohort (1.75 pp)
