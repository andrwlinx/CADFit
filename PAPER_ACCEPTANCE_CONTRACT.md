# Paper acceptance contract — Execute the Program (2026-11-07)

status: proposed (round 0)

Each assertion is checked against the final PDF (paper/main.pdf), its LaTeX source, and the named
result files. Pending preregistered outputs are allowed only as visible placeholders.

A1  Every number in the abstract appears in a table or figure of the main text and traces to a
    named file: results/heldout/h2_primary_local.json, h2_secondary_local_no_section.json,
    results/closed/closed_vs_pipeline.json, results/tools_v3/tools_v3.json.
A2  All numbers in the text and tables are produced by \input{numbers.tex}, which is generated by
    a committed script (bench/paper_numbers.py) from those files; no hand-typed result numbers
    outside numbers.tex.
A3  The primary held-out contrast is reported with its estimate, 95% bootstrap interval, parts
    better/worse and Holm-adjusted p, and is labelled as the preregistered primary.
A4  The recovery amendment is described in the main text as a post-outcome measurement amendment,
    and the primary contrast on the original pre-recovery files (−0.795) is reported next to the
    recovered one, with its cause (299 sandbox-setup failures).
A5  The tools-v3 primary comparison is reported as not significant by the declared sign test
    (p 0.121; Holm 0.243) in the abstract or the first paragraph of its section, and no sentence
    claims that tools v3 improves Opus+CADFit-tools quality.
A6  Opus+code vs pipeline: the paper states superiority only over v3 (interval excludes 0) and
    states that superiority over the trim package is not established (interval includes 0).
A7  The "code" toolset is described as including target inspection (describe_target, section) and
    execution feedback (evaluate, executed checks); it is not called an unaided LLM baseline.
A8  Closed-model settings are stated: model ids, adaptive thinking, effort high, 32k max tokens per
    turn, full native history, budget 40 calls / 30 min, 3 episodes per part.
A9  Failure decomposition for agent arms is reported (delivered-valid counts and no-output
    deadline episodes), and the 472/472 delivered-valid fact is stated.
A10 Every exclusion or rerun is listed with its cause and count: node4002 Opus run (44 episodes,
    $8.95), tools-v3 API-error episodes (239), node3900 preflight stop (53), one ReadTimeout crash,
    the cancelled dx recovery job; total API spend of retained vs discarded episodes is reported.
A11 Cohort disjointness is stated: fresh2 drawn after development; the 40 reserved parts drawn from
    the manifest before any fresh2 outcome; fresh3 drawn after the v3 code/protocol froze and
    excludes every source model of earlier sets. The paper states that fresh2's other 260 parts'
    pipeline outcomes were inspected before the agent studies.
A12 Pending outputs (section-only control and the 4th secondary test, independent rejudge,
    surface agreement) appear only as visibly marked placeholders, and the secondary Holm family
    is stated as 4 tests with the computed 3 marked provisional.
A13 Runtime is reported for the pipeline (mean and median minutes per part per arm) and for the
    agents (mean minutes per episode, model vs tool share), with the note that pipeline runs
    shared nodes (3 parts in parallel) and agents ran 3–8 episodes per node.
A14 The trim result is decomposed into the second repair pass and trim proper.
A15 The limitations paragraph names at least these concrete limits: post-outcome amendment;
    40-part agent cohorts; single benchmark (CADBench hard tier, two splits); code baseline with
    inspection tools; model-version dependence of closed-model results.
A16 Figures 1, 3, 4 exist, each with axis labels, a 95% interval where means are shown, and a
    caption stating cohort, n, and repeats; Figure 2 is labelled as a development-part example.
A17 Main text is at most 9 pages in the ICLR 2027 style; author block anonymous; compiles with
    no undefined references or citations.
A18 Every \cite key resolves to an entry in references.bib that existed before this rewrite or
    was added with a DBLP/CrossRef source; no "[VERIFY]" remains in the final PDF.
